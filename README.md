# 活动席位编排（Seat Arrangement）

基于 **FastAPI + SQLite + 原生 JavaScript** 的活动席位编排 Web 应用。
录入参与者、分区与桌位容量，设置「必须同桌 / 禁止同桌 / 固定席位」规则，
用**可重复的约束搜索**生成安排；可锁定部分席位后重新求解，无解时会指出
涉及的具体规则。

## 功能一览

- **参与者管理**：单个新增，或导入 CSV（`name,note` / `姓名,备注`，UTF-8 与 GBK 均可）
- **分区与桌位**：桌容量上限、分区容量上限（0 表示不限）
- **三类编排规则**
  - 必须同桌（多条规则按传递闭包合并为落座组，整组一起落座）
  - 禁止同桌（组内任意两人不得同桌）
  - 固定席位（某人必须在指定桌位）
- **可重复求解**：基于随机种子的确定性回溯搜索（MRV + 容量裁剪），
  同一种子与同一份数据永远得到同一结果；更换种子可得到不同方案
- **锁定后重排**：在编排图上调整任意席位即自动锁定；重新求解时锁定席位
  保持不动，只重排其余人员
- **无解诊断**：先做结构性预检（规则直接互相矛盾、组超过桌容量、超员等），
  搜索失败时再用删除式过滤（deletion-based MUS）定位「缺一不可」的致冲突规则，
  前端可一键跳到对应规则
- **CSV 导出**：导出 姓名 / 备注 / 分区 / 桌位 / 容量 / 是否锁定
- **一键启动**：Dockerfile + Docker Compose，数据持久化到卷

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up -d --build
```

启动后访问：

- 应用界面：<http://localhost:8000/>
- API 文档（Swagger）：<http://localhost:8000/docs>

首次打开若数据库为空，会自动载入一份演示数据（2 个分区、4 张桌、14 人、
若干规则），可直接点击「生成 / 重新编排」体验。

停止与清理：

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并删除数据
```

### 本地直接运行（不使用 Docker）

需要 Python 3.11+：

```bash
python -m pip install -r requirements.txt
SEAT_DB=./seatarrange.db uvicorn app.main:app --host 0.0.0.0 --port 8000
```

访问 <http://localhost:8000/>。

## 配置项

| 配置 | 说明 | 默认值 |
| --- | --- | --- |
| `SEAT_DB` | SQLite 数据库文件路径，容器内位于数据卷 `/data` | `/data/seatarrange.db` |
| 宿主机端口 | 在 `docker-compose.yml` 的 `ports` 中修改（如 `8080:8000`） | `8000` |

## 使用说明

1. **分区与桌位**：先建分区（设置分区容量上限，0 = 不限），再建桌位并指定
   容量与所属分区。
2. **参与者**：逐个添加，或在「参与者」页签导入 CSV。模板可通过页签内
   「下载模板」获取：
   ```csv
   name,note
   张三,VIP
   李四,
   ```
3. **规则**：在「规则」页签点选参与者创建必须同桌 / 禁止同桌规则，或选择
   一人一桌创建固定席位规则。
4. **生成编排**：顶部设置随机种子，点击「生成 / 重新编排」。相同种子 +
   相同数据 ⇒ 相同安排，方便复现与分享；点「换一个」可随机更换种子。
5. **锁定与重排**：在席位卡上用下拉框调整桌位会自动锁定该席位，也可勾选
   「锁定」复选框。再次点击「生成 / 重新编排」时，锁定席位不动，其余人员
   重新求解；「全部解锁」恢复完全重排，「清空席位」删除所有安排。
6. **无解处理**：页面顶部红色面板会列出冲突原因，并以标签显示涉及的规则
   编号，点击标签跳转到「规则」页签并高亮；删除或放宽所点名的任意一条规则
   后再重新求解即可。
7. **导出**：在「席位编排」页签点击「导出结果 CSV」。

## 求解器说明

- 搜索算法：回溯（Backtracking）+ MRV 变量选择 + 前向检查（容量、分区、
  禁止关系逐层裁剪动态域），随机种子仅用于平局打破，因此结果可重复。
  典型规模（500 人、100 桌并带混合规则）可在约 1 秒内完成求解。
- 必须同桌规则先求并查集闭包，每个连通分量作为不可拆分的落座单位。
- 无解时分两层诊断：
  1. **结构预检**：固定规则互相矛盾、同桌组被钉到不同桌、组超过最大桌容量、
     禁止同桌双方被钉在同一桌、禁止关系形成的互斥团超过可用桌数、
     锁定/固定人数超过桌或分区容量等；
  2. **规则核心（MUS）**：若基线（只保留容量与用户锁定）可行而完整约束无解，
     则逐条尝试删除编排规则，筛出一个不可约的致冲突规则集合展示给用户。
- 规模提示：适用于中小型活动（数百人、数十到上百桌）的即时求解；单次搜索有
  节点上限（50 万）与 30 秒时限，诊断阶段总时限 15 秒（每次尝试 2 秒），
  超时会给出保守提示。

## 项目结构

```
app/
  main.py        # FastAPI 路由、CSV 导入导出、演示数据
  solver.py      # CSP 回溯求解器与无解诊断（无外部依赖，可单测）
  database.py    # SQLite 连接与建表
  static/
    index.html   # 单页界面
    styles.css
    app.js       # 原生 JavaScript 前端
tests/
  test_solver.py # 求解器场景测试
  test_api.py    # API 端到端冒烟测试
Dockerfile
docker-compose.yml
requirements.txt
```
